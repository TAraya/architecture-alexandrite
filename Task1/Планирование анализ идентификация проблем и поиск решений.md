## Планирование: анализ, идентификация проблем и поиск решений

### Общие проблемы системы
- ! потеря нескольких крупных контрактов из-за проблем с заказами
- жалобы от клиентов онлайн-магазина на несвоевременное получение заказов, участившиеся после открытия API MES
- жалобы от клиентов API о том, что они не получили свои заказы
- жалобы от операторов о скорости загрузки первой страницы MES
- растущее недовольство клиентов онлайн-магазина 

### Замечания о системе
- порядок допустимого времени выполнения заказа - недели, порядок числа заказов - до десятка тысяч в месяц и ограничен скорее возможностями производства, чем возможностями расширения ИТ-инфраструктуры
- мы не имеем дело с highload-системой, существующий выбор PostgreSQL и RabbitMQ видится достаточным, даже с учетом обозримого расширения
- ! система нестабильна с функциональной точки зрения, при работе возникает множество ошибок, что критично для бизнеса  
 
### Существующие и потенциально проблемные места в архитектуре системы
- открытый вовне API MES
- API MES выполняет роль инициатора создания заказов, что видится нехарактерным для MES и более близким к онлайн-магазину
- API онлайн-магазина и CRM используют общую БД для интеграции

### Инициативы для их устранения
- разработка отдельного API для B2B-заказчиков (на первых порах возможно хотя бы настроить прокси на nginx)
- увеличение степени покрытия функционала автотестами
- введение логирования
- введение мониторинга
- введение трейсинга
- исследование уровня связанности логики CRM, онлайн магазина и API для B2B-заказчиков, данное исследование позволит выбрать оптимальный подход для дальнейшей декомпозиции системы, т.к. сейчас подходящими видятся 2 варианта:
  1) для CRM выделяется отдельная БД, в которой хранится агрегированная информация по заказам, при этом, заказ (заявка) в онлайн-магазине, API B2B и MES являются отдельными сущностями, на которые заказ-агрегат в CRM хранит ссылки
  2) выделяется отдельный сервис для работы с заказами. CRM, API онлайн-магазина и API B2B становятся его клиентами, также на этот сервис возлагается обязанность по синхронизации заказов с MES

### Видение целевой архитектуры на горизонте полугода:
- для B2B-заказчиков выделен отдельный API
- MES в достаточной степени отделена от остальной системы и изолирована от прямого воздействия извне
- при позитивном развитии ситуации проведено исследование об оптимальной декомпозиции системы

### Приоритетные инициативы на ближайшие полгода:
- разработка отдельного API для B2B-заказчиков
- увеличение степени покрытия функционала автотестами (также подразумевает активный багфикс)
- введение мониторинга/логирования наиболее критичных для бизнеса операций
